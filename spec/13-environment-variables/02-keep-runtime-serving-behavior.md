## keep runtime — serving & behavior

| Variable | Default | Purpose | Read at |
| --- | --- | --- | --- |
| `KEEP_DOCS` | **off** | Part 3 — serve the addable docs/cake module (`/docs/*`). Off by default; the surface needs both the `DocsModule` registered **and** `KEEP_DOCS` truthy — `bootstrapServer` auto-registers `DocsModule` when `KEEP_DOCS` is truthy, so a bare `KEEP_DOCS=1` already satisfies both legs, while a leftover `DocsModule` registered without `KEEP_DOCS` stays inert. Fully open, no auth ([07-cake.md](../07-cake/00-overview.md)). Gate owned by [07-cake/01](../07-cake/01-the-docs-module-docsmodule.md). | Two read sites, one per leg of the AND: `keep/src/foundation/domain/coordinators/bootstrap-server/mod.ts` (auto-registers `DocsModule` when `KEEP_DOCS` is truthy) and `keep/src/foundation/domain/coordinators/docs-module/mod.ts` (the `DocsModule` itself, which also consults `KEEP_DOCS` at serve time so it stays inert when composed onto a Danet app outside `bootstrapServer` — see [07-cake/01](../07-cake/01-the-docs-module-docsmodule.md)) |
| `KEEP_DEV` | — | The `rune dev` status/reload channel (`/docs/_dev`); set by `rune dev`, not by hand. Orthogonal to `KEEP_DOCS`. Dev channel owned by [07-cake/05](../07-cake/05-dev-mode-and-tracing-pages.md). | `keep/src/foundation/domain/coordinators/bootstrap-server/mod.ts` |
| `KEEP_FIXTURES_DIR` | resolved (three-tier, see [07-cake/02](../07-cake/02-the-cake-docs-module.md)) | Overrides the directory for cake/heal fixtures (`cake.json`, scenarios, heal rules) wholesale. Otherwise resolved, in precedence order: the nearest git root's `spec/misc` when that root has a `spec/`, else `<cwd>/spec/misc` when the cwd has one, else the legacy `<cwd>/fixtures` — canonical resolution owned by [07-cake/02](../07-cake/02-the-cake-docs-module.md). | `keep/src/foundation/domain/business/fixtures-store/mod.ts`, `src/rune/entrypoints/sync/mod.ts` |
| `RUNE_ASSERT` | on | The `#assert` runtime. `=off` makes every seam assertion a passthrough (validation disabled — a loud, committed choice, surfaced in prod). Owned by [06-runtime/03](../06-runtime/03-the-assert-runtime-assert.md). | `keep/src/assert/mod.ts` |
| `DENO_ENV` | — | `=production` excludes ghost-stub endpoints from the module registry. This is a **runtime (boot-time) gate**: `rune sync` only emits the `DENO_ENV=production` check into the generated registry code — it never reads the variable itself — and the gate fires when the generated app boots. Independent of `DENO_DEPLOY` (the substrate's Datadog `env:production` tag) — a Deno Deploy run does not imply `DENO_ENV=production`. A production deploy must set `DENO_ENV=production` explicitly to exclude ghost stubs. Ghost-stub lifecycle owned by [04-codegen/03](../04-codegen/03-ghost-stubs-the-typ-ext-lifecycle.md). | `server/bootstrap/modules.ts` (generated, in the produced project — the registry entry sync emits is `DENO_ENV`-gated there, and that gate is evaluated at app boot) |
| `PRIVATE_CLAUDE_URL` | — | The private-Claude heal service the cake's Ask-Claude tier calls (`/docs/_heal`). Its own service, unrelated to keep auth. Heal panel owned by [07-cake/02](../07-cake/02-the-cake-docs-module.md). | `keep/src/foundation/domain/business/heal/mod.ts` |
| `PRIVATE_CLAUDE_TOKEN` | — | Optional `Bearer` token for that heal service. Heal panel owned by [07-cake/02](../07-cake/02-the-cake-docs-module.md). | `keep/src/foundation/domain/business/heal/mod.ts` |
